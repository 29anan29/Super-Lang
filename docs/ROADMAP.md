## M0：垂直切片（3 个月）

### 目标

先跑通全链路：**源码 → 编译器 → LLVM IR → 机器码 → C 链接**。用显式标注（手写 `&`/`&mut`）实现 M0，确保编译器骨架、LLVM 后端、C ABI 三条线独立可验证。自动推导算法在 M1 再开启。

### 详细任务清单

#### 1. 编译器前端

- [ ] **词法分析器（Lexer）**
  - 识别关键字：`fn`, `pub`, `struct`, `enum`, `match`, `if`, `else`, `for`, `unsafe`, `import`, `extern`, `let`, `return`, `out`, `in`
  - 识别标识符、字面量（整数、浮点、字符串、布尔）
  - 识别运算符：`+`, `-`, `*`, `/`, `%`, `==`, `!=`, `<`, `>`, `<=`, `>=`, `and`, `or`, `not`
  - 识别分隔符：`:`, `,`, `.`, `->`, `(`, `)`, `{`, `}`, `[`, `]`, `#`, `!`, `*`, `&`, `;`
  - 支持单行注释 `//` 和多行注释 `/* ... */`
  - 输出：Token 流

- [ ] **语法分析器（Parser）**
  - 构建 AST，支持以下语法结构：
    - 函数定义：`fn name(params): return_type` / `pub fn name(params): return_type`
    - 公开函数：`pub fn`（可导出给 C）
    - 结构体定义：`struct Name: field_type ...`
    - 枚举定义：`enum Name: val1, val2, ...`
    - match 表达式：`match x: case val: ... case _: ...`
    - if/else 控制流：`if condition: ... else: ...`
    - for 循环：`for condition: ...`
    - unsafe 块：`unsafe: ...`
    - 变量声明：`let x: type = value` / `x type = value`
    - import 语句：`import "module"`
    - extern "C" 块：`extern "C": import "header" fn ...`
    - 显式借用标注：`&x int`, `&mut x int`, `*x int`
    - 赋值与复合赋值：`=`, `+=`, `-=`, `*=`, `/=`, `%=`
    - 自增自减：`++`, `--`
  - 输出：AST 抽象语法树

- [ ] **Hindley-Milner 类型推断**
  - 函数体内变量、表达式类型全自动推断
  - 支持泛型函数（类型参数自动推断）
  - 支持代数数据类型（struct、enum）的类型推导
  - 公共 API（导出函数签名、公开 struct 字段）要求显式类型标注
  - 实现算法：约束生成 → 约束求解（合一）
  - 输出：带类型标注的 AST

- [ ] **MIR/SSA 构造**
  - 将 AST 转换为中间表示（MIR）
  - 构造 SSA 形式的中间代码
  - 实现基本 CFG（控制流图）构建
  - 为借用检查 pass 做准备
  - 输出：MIR + SSA 表示

- [ ] **LLVM IR 生成**
  - 将 MIR/SSA 转换为 LLVM IR
  - 使用 LLVM C API 或 Inkling/llvmlite 绑定
  - 支持基本类型映射：int → i64, float → double, bool → i1, string → i8*
  - 支持函数定义、分支、循环、返回的 IR 生成
  - 输出：LLVM IR 模块

- [ ] **LLVM 后端**
  - 配置 LLVM 目标架构：x86_64 Linux（首版）
  - 优化级别选择（O0/O1/O2）
  - 生成目标机器码
  - 输出：`.o` 目标文件、`.a` 静态库、`.so` 动态库

- [ ] **C 导出（FR-4.1）**
  - `export "C" fn` 标记的函数生成未 mangle 符号
  - 自动生成 C 头文件（`.h`）
  - 函数签名映射：SUPER 类型 → C 类型（int → int32_t, string → char*, etc.）
  - 支持变长参数（`...`）导出
  - 输出：C 头文件 + 目标文件

- [ ] **C 互操作基础（FR-4.2）**
  - C 类型映射：固定宽度整数（int8_t, int32_t, int64_t）、浮点（float, double）、指针
  - `#[repr(C)]` struct 布局与 C 一致
  - `extern "C"` 块内导入 C 头文件中的函数
  - 输出：可链接的 C 互操作模块

#### 2. 工具链

- [ ] **构建命令**
  - `super build`：从源码到静态库/动态库/可执行文件
  - `super build --lib`：生成库
  - `super build --bin`：生成可执行文件
  - 输出：编译后的产物

- [ ] **错误诊断系统（FR-5.3）**
  - 位置信息：文件名 + 行号 + 列号
  - 错误类型：语法错误、类型错误、借用错误
  - 修复建议：输出可能的修复方案
  - 输出：人话可读的错误信息

#### 3. 测试验证

- [ ] **编译器能成功构建 hello world 程序**
  ```super
  export "C" fn main() int:
      out("hello, super")
      return 0
  ```
  - 编译通过，生成 `.o` 文件

- [ ] **生成的 `.o` 文件可被 gcc 链接**
  ```bash
  gcc hello.o -o hello && ./hello
  ```
  - 输出 `hello, super`

- [ ] **支持基本的算术表达式和控制流**
  ```super
  fn add(a int, b int) int:
      return a + b
  ```
  - 加减乘除、if/else、for 循环均能编译运行

- [ ] **支持 `struct` 定义与字段访问**
  ```super
  struct Point:
      x int
      y int
  ```
  - struct 定义、字段访问均能编译运行

#### 4. M0 交付物

- [ ] 可编译运行的编译器二进制（`super` 命令）
- [ ] 完整的词法分析器 + 语法分析器 + 类型推断器
- [ ] LLVM IR 生成器 + 后端
- [ ] C 导出功能（生成 `.h` 头文件）
- [ ] 错误诊断系统
- [ ] 能编写调用 zlib 的程序并正确链接运行

## M1：MVP（+4 个月）

### 目标

开启**自动借用推导**——这是 SUPER 的核心差异化特性。用户无需写 `&`/`&mut`/生命周期，编译器自动为每个参数推导借用约定。同时实现 drop 插入和 bindgen 原型。

### 详细任务清单

#### 1. 自动借用推导（FR-2.1~2.7）

- [ ] **推导算法核心（FR-2.1~2.3）**
  - 初始化：所有参数假设为 `borrowed`（最小特权原则）
  - SSA 后的流敏感扫描：
    - 仅读参数 → 保持 `borrowed`
    - 存在写路径 → 升级为 `inout`
    - 被存储/返回/转移 → 升级为 `owned`
  - 读写冲突消解（FR-2.3）：
    - 同一变量的读写冲突按"并发读/独占写"策略分割借用区间
    - 等价于 NLL（Non-Lexical Lifetimes）语义
  - 实现算法：数据流分析 + 借用区间分割
  - 输出：每个参数的推定借用约定（borrowed/inout/owned）

- [ ] **生命周期为编译器内部区域变量（FR-2.4）**
  - 生命周期不进入用户可见语法
  - 通过 region inference 求解
  - 实现算法：生命周期图 → 区域变量约束求解
  - 用户完全无感知

- [ ] **显式覆盖通道（FR-2.5）**
  - 用户可用最短语法强制指定约定：
    - `*x int` → owned（移动）
    - `&x int` → borrowed（只读）
    - `&mut x int` → inout（可变借用）
  - 用于消歧和性能微调
  - 实现：显式标注覆盖推导结果

- [ ] **推导诊断（FR-2.6）**
  - 借用冲突报错必须输出：
    - 推导依据（"此参数被推导为可变借用，因为第 N 行写入了它"）
    - 修复建议代码片段
  - 实现：错误诊断模块与推导 pass 联动
  - 输出：人话可读的借用冲突错误信息

- [ ] **跨过程推导（FR-2.7）**
  - 已导出函数的推导结果固化为签名契约并缓存
  - 调用方直接使用缓存结果，无需重新推导
  - 实现：签名表 + 缓存机制
  - 输出：跨过程一致的借用约定

#### 2. 内存管理 — Drop 插入（FR-3.1~3.6）

- [ ] **栈分配优先（FR-3.1）**
  - 编译期已知大小的值默认栈分配
  - 实现：逃逸分析 + 栈分配决策
  - 输出：栈分配的局部变量

- [ ] **确定性析构 — Drop 插入 pass（FR-3.2）**
  - 基于活跃区间在 CFG 上自动插入 drop 调用
  - 作用域结束语义与 RAII 一致
  - 实现：CFG 遍历 → 活跃区间分析 → 插入 drop 调用
  - 输出：带 drop 调用的 MIR

- [ ] **用户自定义 Drop（FR-3.3）**
  - 析构函数按逆序确定性执行
  - 可用于包装 C 资源（文件句柄、连接等）
  - 语法：`fn drop(&self)` 或 `impl Drop for Type: fn drop(&self)`
  - 输出：自动调用析构的代码

- [ ] **堆分配类型（FR-3.4）**
  - Vec / String / Box 类：编译期证明唯一 owner
  - 释放点唯一，无 double-free 风险
  - 实现：引用计数编译期证明或所有权跟踪
  - 输出：安全的堆分配类型

- [ ] **Drop 插入优化（FR-3.5）**
  - 合并相邻 drop 调用
  - 消除 Copy 类型的 drop
  - 内联平凡 drop
  - 实现：优化 pass
  - 输出：优化后的 MIR

- [ ] **运行时保证（FR-3.6）**
  - 无 GC 线程、无 stop-the-world
  - 无引用计数元数据（除非显式使用）
  - 无运行时安全检查（safe 子集零运行时开销）
  - 输出：纯编译期保证

#### 3. bindgen 原型（FR-4.3）

- [ ] **C 头文件解析**
  - 基于 libclang 解析 C 头文件
  - 提取函数签名、struct 定义、enum 定义
  - 输出：C 抽象语法树

- [ ] **安全绑定生成**
  - 将 C 签名映射为 SUPER 签名
  - 生成安全包装函数
  - 不透明指针类型封装（FR-4.4）
  - 输出：SUPER 绑定代码

#### 4. 错误诊断系统完善（FR-5.3）

- [ ] **推导错误诊断**
  - 借用冲突：推导依据 + 修复建议
  - 类型不匹配：期望类型 vs 实际类型
  - 未定义变量：建议拼写修正
  - 输出：三段式错误信息（位置 + 原因 + 修复建议）

- [ ] **编译性能**
  - 中型项目（5 万行）全量编译 ≤ 30s
  - 实现：增量编译（后续版本）
  - 输出：编译性能指标

#### 5. M1 交付物

- [ ] 自动推导版编译器（无需手写 `&`/`&mut`）
- [ ] 借用推导核心算法（流敏感扫描 + 冲突消解）
- [ ] Drop 插入 pass（确定性析构）
- [ ] bindgen 原型（解析 C 头文件，生成安全绑定）
- [ ] 错误诊断系统（位置 + 推导过程 + 修复建议）
- [ ] 80% 的示例代码不含任何内存管理显式语法
- [ ] 借用冲突编译错误包含推导依据说明
- [ ] drop 自动插入，作用域结束自动调用
- [ ] bindgen 可为简单的 C 头文件生成绑定

## 技术决策快照

| 决策 | 选项 | 依据 |
|------|------|------|
| **类型推断核心** | Hindley-Milner | PRD FR-1.1，成熟且支持泛型 |
| **借用检查层级** | MIR/SSA 层 | PRD 5.1，复用 rustc 经验，难度低于 AST |
| **后端选择** | LLVM | PRD 5.3，C ABI 天然兼容 |
| **内存管理** | 编译器插入 drop + RAII | PRD FR-3.2~3.5，无 GC，确定性释放 |
| **C 互操作** | `extern "C"` + bindgen | PRD FR-4.1~4.7，零运行时开销 |
| **错误诊断** | 位置+推导过程+修复建议 | PRD FR-5.3，P0 需求 |
| **借用覆盖符号** | `*`/`&`/`&mut` | FR-2.5，最短语法强制指定 |
| **枚举写法** | `enum Name: val1, val2` | 与 struct/if 保持 colon 风格一致 |
| **unsafe 语法** | `unsafe:` | Python 风格，最小学习成本 |
| **Option/Result 声明** | 边界显式 | FR-1.1/FR-1.2 内部推断，API 标注 |

## 核心风险与对策

| 风险 | 等级 | 对策 | 触发时点 |
|------|------|------|----------|
| **推导精度困境**：过保守则频繁要求显式干预，过激进则拒绝合法程序 | 高 | M1 过程内保守推导，保留显式覆盖通道（`*x int`/`&x int`/`&mut x int`） | M1 开始时 |
| **C 边界安全豁免失准**：`#[safe_c]` 形同虚设或误伤 | 高 | 豁免白名单从严起步（只放行无指针参数、无堆返回的纯函数），建立标注审查清单 | 持续，M1 后 |
| **跨过程推导复杂度超预期** | 中 | 降级预案：M1/M2 仅过程内推导 + 签名固化，跨过程全局求解推迟到 M3 后 | M2 阶段 |
| **错误诊断质量不足**导致"自动推导失败时更难懂" | 中 | 诊断系统作为 P0 需求与推导 pass 同步开发，每个推导失败分支必须有人话解释 | 持续开发 |
| **生态冷启动**（无包、无库） | 中 | 以 C 互操作为核心冷启动策略——bindgen 让任意 C 库数分钟内可用 | M1~M3 |
| **LLVM 编译速度不达标** | 低 | NFR-2 设为硬指标；必要时引入增量编译（远期） | M2 验收时 |
| **自举编译器复杂度超预期** | 中 | M2 先实现自举编译流程，不要求完全自举时立即替换 | M2 阶段 |
