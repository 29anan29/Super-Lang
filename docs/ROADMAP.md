# 语言实现路线图

## 目标
打造一门“Rust 安全 + Python 好学”的系统级编程语言，并行踩两条腿：
- **安全**：编译期内存安全、无 GC、RAII 资源管理
- **易学**：无显式所有权/生命周期标注、对 Python 用户零门槛

---

## 里程碑规划

| 阶段 | 周期 | 目标 | 验收标准 |
|------|------|------|----------|
| **M0：垂直切片** | 3 个月 | 显式标注版语言（需手写 `&`/`&mut`）+ LLVM 后端 + C 导出 | 能编写调用 zlib 的程序并正确链接运行 |
| **M1：MVP** | +4 个月 | HM 推断 + 过程内借用推导 + drop 插入 + bindgen 原型 | FR-1.1/1.3、FR-2.1~2.3/2.6、FR-3.1~3.4、FR-4.1/4.2 全部达标 |
| **M2：自举候选** | +6 个月 | 跨过程推导 + RAII 资源管理完善 + 诊断系统成型 | 30 个真实 C 库绑定案例通过；性能基准达到 NFR-1 |
| **M3：公测** | +6 个月 | 包管理 + 文档 + 教程（零标注入门路径） | 10 个外部早期用户完成 S1~S3 场景验证 |

---

## 阶段详情

### M0：垂直切片（3 个月）
- 词法分析、语法分析
- Hindley-Milner 类型推断（显式标注版）
- LLVM IR 生成
- `extern "C"` 导出函数
- **交付物**：可编译运行的二进制库/可执行文件
- **关键代码示例**：
  ```lang
  // 需要显式标注借用
  fn add(a: int, b: int) -> int:
      return a + b
  ```

### M1：MVP（+4 个月）
- 过程内自动借用推导（FR-2.1~2.3）
- drop 插入 pass（FR-3.2）
- bindgen C 头文件解析原型（FR-4.3）
- **交付物**：自动推导版编译器
- **关键代码示例**（无需显式标注）：
  ```lang
  // 借用自动推导
  fn add(a int, b int) int:
      return a + b
  // 已知有写入路径
  fn conflict(a int):
      a = 10  // 编译器推断为 inout
  ```

### M2：自举候选（+6 个月）
- 跨过程推导固化为签名契约（FR-2.7）
- RAII 资源管理完善
- 错误诊断系统（FR-5.3）
- 30+ 真实 C 库绑定
- **交付物**：可自举的编译器
- **性能基准**：与等价 Rust 代码差距 ≤ 10%

### M3：公测（+6 个月）
- 包管理系统（FR-5.4）
- 官方教程（零标注入门路径）
- 10 个外部早期用户验证
- **交付物**：公开发行版

## 核心风险

| 风险 | 等级 | 对策 |
|------|------|------|
| 推导精度困境 | 高 | M1 过程内保守，保留显式覆盖通道 |
| C 边界安全豁免 | 高 | 白名单从严，仅放行纯函数 |
| 编译性能不达标 | 中 | NFR-2 硬指标；增量编译远期 |
| 错误诊断质量差 | 中 | 诊断系统 P0 同步开发 |
