# 语言实现路线图

## 目标
打造一门“Rust 安全 + Python 好学”的系统级编程语言，并行踩两条腿：
- **安全**：编译期内存安全、无 GC、RAII 资源管理
- **易学**：无显式所有权/生命周期标注、对 Python 用户零门槛

---

## 里程碑规划

| 阶段 | 周期 | 目标 | 验收标准 |
|------|------|------|----------|
| **M0：垂直切片** | 3 个月 | 显式标注版语言（需手写 `&`/`&mut`）+ LLVM 后端 + C 导出 | 能编写调用 zlib 的程序并正确链接运行 |
| **M1：MVP** | +4 个月 | HM 推断 + 过程内借用推导 + drop 插入 + bindgen 原型 | FR-1.1/1.3、FR-2.1~2.3/2.6、FR-3.1~3.4、FR-4.1/4.2 全部达标 |
| **M2：自举候选** | +6 个月 | 跨过程推导 + RAII 资源管理完善 + 诊断系统成型 | 30 个真实 C 库绑定案例通过；性能基准达到 NFR-1 |
| **M3：公测** | +6 个月 | 包管理 + 文档 + 教程（零标注入门路径） | 10 个外部早期用户完成 S1~S3 场景验证 |

## 阶段详情

### M0：垂直切片（3 个月）

#### 1.1 核心任务
- **词法分析**：识别关键字、标识符、字面量、运算符
- **语法分析**：构建 AST，支持 `fn`/`struct`/`enum`/`match`/`if`/`for`/`unsafe`
- **Hindley-Milner 类型推断**：函数体内变量、表达式全自动推断
- **LLVM IR 生成**：中间表示，为后端做准备
- **C 导出**：`extern "C"` 函数生成未 mangle 符号

#### 1.2 交付物
- 可编译运行的编译器二进制
- 能编写如下程序：
```lang
// M0 级别：需要显式标注
fn add(a: int, b: int) -> int:
    return a + b

// C 导出测试
export "C" fn main() int:
    return 0
```

#### 1.3 验收标准
- [ ] 编译器能成功构建 hello world 程序
- [ ] 生成的 `.o` 文件可被 gcc 链接
- [ ] 支持基本的算术表达式和控制流
- [ ] 支持 `struct` 定义与字段访问

---

### M1：MVP（+4 个月）

#### 2.1 核心任务
- **过程内自动借用推导**（FR-2.1~2.3）：
  - 初始化：所有参数假设为 `borrowed`
  - SSA 后的流敏感扫描
  - 规则：仅读→borrowed；有写路径→inout；被存储/返回→owned
  - 读写冲突按“并发读/独占写”策略分割借用区间
- **drop 插入 pass**（FR-3.2）：基于活跃区间在 CFG 上自动插入 drop 调用
- **bindgen 原型**（FR-4.3）：解析 C 头文件，生成安全绑定
- **错误诊断系统**（FR-5.3）：位置+推导过程+修复建议三段式输出

#### 2.2 交付物
- 自动推导版编译器
- 以下代码无需显式标注：
```lang
// 借用自动推导，M1 达标
fn add(a int, b int) int:
    return a + b

// 有写入路径被推断为 inout
fn conflict(a int):
    a = 10  // 编译器推断为可变借用
    print(a)
```

#### 2.3 验收标准
- [ ] 80% 的示例代码不含任何内存管理显式语法
- [ ] 借用冲突编译错误包含推导依据说明
- [ ] drop 自动插入，作用域结束自动调用
- [ ] bindgen 可为简单的 C 头文件生成绑定

---

### M2：自举候选（+6 个月）

#### 3.1 核心任务
- **跨过程推导**（FR-2.7）：已导出函数的推导结果固化为签名契约并缓存
- **RAII 资源管理完善**：任意类型的 drop 实现，包装 C 资源（文件句柄、连接等）
- **单元测试覆盖率 ≥ 85%**：核心推理 pass 的测试
- **性能基准**：与等价 Rust 代码差距 ≤ 10%（选定基准集）

#### 3.2 交付物
- 可自举的编译器（用自身编译自身）
- 30+ 真实 C 库绑定案例（sqlite3, zlib, 等）
- 完善的错误诊断信息
- 基准测试报告

#### 3.3 验收标准
- [ ] 30 个真实 C 库绑定全部通过编译和运行
- [ ] NFR-1：与 Rust 同等基准测试，差距 ≤ 10%
- [ ] NFR-2：中型项目（5万行）全量编译 ≤ 30s
- [ ] NFR-3：hello world 静态二进制 ≤ 1MB
- [ ] 核心推导 pass 单元测试覆盖率 ≥ 85%

## 技术决策快照

| 决策 | 选项 | 依据 |
|------|------|------|
| **类型推断核心** | Hindley-Milner | PRD FR-1.1，成熟且支持泛型 |
| **借用检查层级** | MIR/SSA 层 | PRD 5.1，复用 rustc 经验，难度低于 AST |
| **后端选择** | LLVM | PRD 5.3，C ABI 天然兼容 |
| **内存管理** | 编译器插入 drop + RAII | PRD FR-3.2~3.5，无 GC，确定性释放 |
| **C 互操作** | `extern "C"` + bindgen | PRD FR-4.1~4.7，零运行时开销 |
| **错误诊断** | 位置+推导过程+修复建议 | PRD FR-5.3，P0 需求 |
| **借用覆盖符号** | `*`/`&`/`&mut` | FR-2.5，最短语法强制指定 |
| **枚举写法** | `enum Name: val1, val2` | 与 struct/if 保持 colon 风格一致 |
| **unsafe 语法** | `unsafe:` | Python 风格，最小学习成本 |
| **Option/Result 声明** | 边界显式 | FR-1.1/FR-1.2 内部推断，API 标注 |

## 核心风险与对策

| 风险 | 等级 | 对策 | 触发时点 |
|------|------|------|----------|
| **推导精度困境** | 高 | M1 过程内保守推导，保留显式覆盖通道（如 `*x int`） | M1 开始时 |
| **C 边界安全豁免失准** | 高 | 白名单从严，仅放行无指针参数、无堆返回的纯函数 | 持续，M1 后 |
| **跨过程推导复杂度超预期** | 中 | 降级预案：M1/M2 仅过程内推导 + 签名固化，跨过程推迟到 M3 后 | M2 阶段 |
| **错误诊断质量不足** | 中 | 诊断系统作为 P0 需求与推导 pass 同步开发，每个失败分支必须有人话解释 | 持续开发 |
| **编译性能不达标** | 中 | NFR-2 硬指标；必要时引入增量编译（远期） | M2 验收时 |
| **生态冷启动** | 中 | 以 C 互操作为核心冷启动策略——bindgen 让任意 C 库数分钟内可用 | M1~M3 |
