# 架构设计

## 概述

SUPER 编译器整体架构分为四层：前端、中端、后端、工具链。

```
源码（.super）
  │
  ▼
┌─────────────────────────────────┐
│           前端（Frontend）         │
│  Lexer → Parser → 类型推断        │
│  输出：带类型标注的 AST            │
└─────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────┐
│           中端（Midend）           │
│  MIR/SSA → 借用推导 → region     │
│       → drop 插入 → 优化          │
│  输出：优化后的 MIR               │
└─────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────┐
│           后端（Backend）          │
│  MIR → C 代码生成器 → C 源码      │
│       → gcc/clang → 机器码         │
│  输出：.o / .a / .so             │
└─────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────┐
│           工具链（Toolchain）       │
│  构建命令 + 错误诊断 + 包管理       │
└─────────────────────────────────┘
```

## 分层职责

### 前端

- 词法分析：识别关键字、标识符、字面量、运算符
- 语法分析：构建 AST
- 类型推断：HM 风格类型推断，函数体变量自动推断

### 中端

- MIR/SSA 构造：将 AST 转换为中间表示
- 借用推导：自动推导 borrowed/inout/owned
- Region inference：生命周期求解
- Drop 插入：确定性析构
- 优化：合并、消除、内联

### 后端

- C 代码生成：将 MIR 转换为 C 源码
- 类型映射：SUPER 类型 → C 类型
- 调用 gcc/clang 完成最终编译

### 工具链

- 构建命令：`super build`
- 错误诊断：位置 + 推导过程 + 修复建议
- 包管理：依赖声明、下载、构建集成

## 数据流

| 阶段 | 输入 | 输出 |
|------|------|------|
| 词法分析 | 源码字符串 | Token 流 |
| 语法分析 | Token 流 | AST |
| 类型推断 | AST | 带类型标注的 AST |
| MIR 构造 | 带类型标注的 AST | MIR + SSA |
| 借用推导 | MIR + SSA | 带借用标注的 MIR |
| Drop 插入 | 带借用标注的 MIR | 优化后的 MIR |
| C 代码生成 | 优化后的 MIR | C 源码（.c） |
| C 编译 | C 源码 | .o / .a / .so |

## 关键设计决策

1. **借用检查在 MIR/SSA 层做**：复用 SSA def-use 链，实现难度远低于语法树方案
2. **借用检查与类型检查解耦**：先类型推断，再借用分析，两阶段错误不互相污染
3. **后端生成 C 代码**：利用 gcc/clang 成熟编译管线，零自研后端成本
4. **C ABI 第一公民**：导出符号即标准 C 调用约定，无需额外适配层
