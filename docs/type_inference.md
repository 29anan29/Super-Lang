# 类型推断设计

## 概述

SUPER 采用 Hindley-Milner 风格类型推断。函数体内部变量、表达式类型全部自动推断，无需标注。公共 API（导出函数签名、公开 struct 字段）要求显式类型标注。

## 核心算法

### 约束生成 → 约束求解

```
1. 遍历 AST，为每个表达式生成类型约束
2. 收集所有约束，形成约束集合
3. 使用合一（Unification）算法求解约束
4. 若成功 → 代入类型映射，得到完整类型标注
5. 若失败 → 报告类型错误
```

### 类型规则（选）

**变量声明：**
```
Γ ⊢ value : T   →   Γ ⊢ x : T
```

**函数调用：**
```
Γ ⊢ f : (T1 → T2)   Γ ⊢ arg : T1   →   Γ ⊢ f(arg) : T2
```

**二元运算：**
```
Γ ⊢ a : int   Γ ⊢ b : int   →   Γ ⊢ a + b : int
Γ ⊢ a : float   Γ ⊢ b : float   →   Γ ⊢ a + b : float
```

**函数定义：**
```
Γ, x:T1 ⊢ body : T2   →   Γ ⊢ fn(x:T1): T2
```

**泛型函数：**
```
Γ ⊢ fn(x: α): α     →   Γ ⊢ fn : ∀α. α → α
```

### 类型环境（Γ）

- 维护变量名到类型的映射
- 函数定义时更新环境
- 作用域规则：块级作用域

## 类型映射

| SUPER 类型 | C 类型 |
|-----------|--------|
| `int` | `int` |
| `float` | `double` |
| `bool` | `int` |
| `string` | `char*` |
| `void` | `void` |

## 泛型支持

- 单态化（Monomorphization）：泛型函数在编译时根据调用点具体化
- 类型约束：泛型参数需支持所需操作（如加法、比较）
- 实现：实例化时将泛型替换为具体类型

## 错误诊断

- 类型不匹配：报告期望类型 vs 实际类型
- 未推断出类型：报告无法推断的变量位置
- 循环依赖：报告类型推断循环

## 示例

```super
fn add(a int, b int) int:
    return a + b      // a: int, b: int, 返回 int

x = 10              // x: int（自动推断）
y = "hello"         // y: string（自动推断）
```
