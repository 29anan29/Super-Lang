# 错误诊断设计

## 概述

错误诊断系统是 SUPER 的 P0 需求。编译错误必须包含三段式信息：出错位置、原因、修复建议。

## 诊断结构

```
错误位置：文件名:行号:列号
错误类型：简要分类
原因说明：为什么出错（人话可读）
修复建议：具体的修改方案代码片段
```

## 错误分类

### 语法错误

- 缺少右括号、冒号、分号
- 关键字拼写错误
- 非法字符

示例：
```
错误：src/main.super:5:3
原因：期望 ')' 但找到 ';'
修复：将 ';' 改为 ')'
```

### 类型错误

- 类型不匹配
- 未定义变量
- 无法推断类型

示例：
```
错误：src/main.super:8:10
原因：函数 add 期望参数类型为 int，但传入的是 string
修复：将参数改为 int 类型，或使用 to_int() 转换
```

### 借用错误

- 读写冲突
- 借用超出生命周期
- 所有权已转移

示例：
```
错误：src/main.super:12:5
原因：参数 x 被推导为可变借用，因为第 15 行写入了它。
但 y 在第 13 行借用了 x，第 15 行的写入与 y 的借用冲突。
修复建议：
  1. 将 y 的使用移到第 15 行写入之后
  2. 或将 x 复制一份：let x_copy = x
```

## 错误恢复

- 语法错误：跳过当前语句，继续解析后续内容
- 类型错误：假设正确类型继续推断，报告所有错误
- 借用错误：标记冲突区域，继续分析其他函数

## 诊断实现

### 位置追踪

- Token 级别：记录每个 Token 的源码位置
- AST 节点：携带源码位置范围
- 错误信息：绑定到具体节点位置

### 原因生成

- 类型错误：根据约束求解结果生成
- 借用错误：根据推导算法的中间状态生成
- 语法错误：根据期望 token 和实际 token 生成

### 修复建议

- 常见问题模式匹配
- 自动生成候选修复方案
- 代码片段高亮展示

## 诊断测试

- 单元测试：每种错误类型至少 3 个测试用例
- 集成测试：完整错误链路验证
- 覆盖率：诊断分支覆盖率 ≥ 85%
