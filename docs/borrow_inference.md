# 借用推导设计（核心）

## 概述

自动借用推导是 SUPER 的核心差异化特性。编译器按流敏感分析为每个参数自动选择 `borrowed`/`inout`/`owned`，用户无需手写 `&`/`&mut`/生命周期。

## 推导规则

| 条件 | 推导结果 |
|------|----------|
| 参数仅被读取 | `borrowed`（只读借用） |
| 参数存在写路径 | `inout`（可变借用） |
| 参数被存储/返回/转移 | `owned`（移动语义） |

## 算法流程

```
1. 初始化：所有参数假设为 borrowed（最小特权）
2. SSA 化：将函数体转换为 SSA 形式
3. 流敏感扫描：遍历 SSA 定义-使用链
   - 读取操作 → 保持 borrowed
   - 写操作 → 升级为 inout
   - 存储/返回/转移 → 升级为 owned
4. 冲突消解：读写冲突按"并发读/独占写"策略分割借用区间
5. 导出固化：推导结果固化为签名契约并缓存
```

## SSA 构造

### SSA 形式要求

- 每个变量只能赋值一次
- φ 函数合并控制流交汇处的值
- 便于进行数据流分析

### CFG 构建

- 基本块：顺序执行的指令集合
- 控制边：跳转关系
- φ 节点：控制流交汇处的值合并

## 冲突消解（NLL 等价语义）

### 读写冲突

当同一变量在同一作用域内既有读又有写时：

1. 识别写操作的位置
2. 将借用区间按写操作分割
3. 读操作和写操作不在同一借用区间内则合法

### 示例

```super
fn example(x int):
    print(x)      // x: borrowed（仅读）
    x = 10        // x 升级为 inout（有写路径）
    print(x)      // x: inout
```

```super
fn conflict(x int):
    y = x         // y 借用 x（读）
    x = 10        // x 升级为 inout（写）
    print(y)      // 错误：y 的借用区间与 x 的写操作冲突
```

## 生命周期处理

- 生命周期为编译器内部区域变量，不进入用户可见语法
- 通过 region inference 求解
- 基于 SSA def-use 链确定变量活跃区间
- 借用的生命周期不能超过被借用值的生命周期

## 显式覆盖通道

用户可通过最短语法强制指定约定：

| 标注 | 含义 |
|------|------|
| `&x int` | borrowed（只读） |
| `&mut x int` | inout（可变借用） |
| `*x int` | owned（移动） |

## 推导诊断

借用冲突报错包含：
- 推导依据：为什么推导为某个约定
- 冲突位置：具体的读写冲突
- 修复建议：如何修改代码消除冲突

示例错误：
```
错误：参数 x 被推导为可变借用，因为第 N 行写入了它。
但 y 在第 M 行借用了 x，第 N 行的写入与 y 的借用冲突。
建议：将 y 的使用移到写入之后，或将 x 复制一份。
```

## 跨过程推导

- 已导出函数的推导结果固化为签名契约
- 调用方直接使用缓存结果
- 缓存失效：依赖文件变更时重新推导
